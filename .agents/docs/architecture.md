# Архитектура

## Цель

Минимальная демонстрация полного пути видеокадра на одном Mac:

```text
окно приложения
  -> ScreenCaptureKit
  -> ограниченная очередь кадров
  -> FFmpeg H.264 encoder
  -> собственный протокол / TCP
  -> FFmpeg decoder
  -> SDL3 renderer
  -> метрики + latest-frame.jpg
  -> локальный API клиента
  -> agent harness + мультимодальная LLM
```

## Границы компонентов

- `protocol` не зависит от UI, FFmpeg или API операционной системы.
- Сервер явно выбирает одно окно, захватывает его и кодирует видеопакеты.
- Клиент принимает сообщения, декодирует, показывает последний доступный кадр
  и публикует наблюдаемые метрики.
- Агент не читает память приложения и не угадывает состояние. Он использует
  локальный API клиента и сохранённый последний кадр.

## Модель выполнения

Захват, кодирование и отправка разделены ограниченными очередями. При
перегрузке удаляется устаревший кадр: для интерактивного видео свежесть важнее
полной доставки всех кадров. TCP выбран для первого рабочего варианта, чтобы
быстро получить корректный framing; ограниченные очереди не позволяют TCP
backpressure бесконечно увеличивать пользовательскую задержку.

## Этапы реализации

1. Заголовок протокола и синтетические пакеты. — готово
2. TCP server/client и синтетические изображения. — готово
3. FFmpeg encode/decode.
4. ScreenCaptureKit с явным выбором окна.
5. SDL3-рендеринг и метрики.
6. Локальный API, latest-frame и агентские tools/evals.

Переход к следующему этапу делается только после исполняемой проверки текущего.
